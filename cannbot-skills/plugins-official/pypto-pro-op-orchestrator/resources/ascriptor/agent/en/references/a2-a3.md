# A2/A3 CCE authoring

Use `ascriptor.a2` or `ascriptor.a3` with `backend='cce'` for the
declared A2/A3 forms. Check the device and operation domain in the owner API
contracts, then run the task workload on its assigned device. The complete
source identity is [sources.json](../../../sources.json).

A2/A3 vector operations act on UB tensors with explicit repeats/counts, block
strides and sticky mask state. They do not use A5 register/VF kernels. Read the
[A2 vector API](../../../library/docs/api/a2-vectors.md), then study the complete
[FMA unit](../../../library/examples/api/a2_fma). Its input tail,
independent reference and every case form one runnable folder of four files. It is the
library's example, not a skeleton for yours: while writing, [`OpExec` and your own
comparison](development-execution.md) are enough, and an A2 algorithm demo is found with
`--device a2` on the [example route](../ROUTER.md). From inside that folder:

```bash
python main.py --list
python main.py --launcher sim
python main.py --launcher pipesim
python main.py --launcher board --backend cce --device a2
```

`--launcher board` runs on the box that holds the card: take the exported directory there
(the unit's README says how to export it) and start it there, because [no launcher reaches another machine](development-execution.md#on-hardware);
`sim` and `pipesim` run anywhere. Use `a3` for an A3 board. Follow the [runtime procedure](../runtime-and-maintenance.md#hardware-first)
for device checks, isolation and hardware-first validation. Functional and pipe
models do not prove vendor compilation or silicon behavior.

For cube work, read [cube](../../../library/docs/api/cube.md) and the exact
unit's physical L1/L0 geometry. A2/A3 cube-to-vector handoff uses GM with
explicit ownership; A5 L0C-to-UB patterns do not transfer automatically.
Packed INT4 MMAD consumes complete bytes: an odd logical K needs the unused
high nibble cleared. The [INT4 unit](../../../library/examples/api/a2_int4_tail)
normalizes private carriers on the device and preserves arbitrary input padding.

The [anchor-mask demo](../../../kernels/ascriptor_kernels/algorithms/a2_anchor_mask)
provides independent sliding-window and synthetic-causal options. Its `reference.py` owns the
boundaries and `python main.py --list` prints all 20 cases with what each one is the only one
to exercise. A2/A3 support is CCE-only by product scope;
other backends are outside the plan. The separate A5PR facade, undeclared
convolution debug shapes and optimizer package ABI integration are outside this
release's qualification.
