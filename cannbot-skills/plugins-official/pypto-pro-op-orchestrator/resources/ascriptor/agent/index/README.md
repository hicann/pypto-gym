# Find an API or example

Use the [API entry](../../library/docs/api/README.md) for topic guides and the
[manifest](../../library/docs/api/manifest.json) for a declared name, signature,
device scope and actual usage. Read one matching entry rather than the entire manifest.
The [API examples](../../library/examples/api/README.md) teach primitives; the
[kernel gallery](../../kernels/README.md) holds complete runnable algorithms. Neither retains a
source, dependency or validation stage: both are four files you run, and a measurement is a
fresh result scoped by its workload and source snapshot.

[kernels.json](kernels.json) is generated navigation over every current API example and kernel
demo. [patterns.json](patterns.json) supplies bilingual task
phrases, guides and preferred examples with explicit semantic distinctions. Neither file
copies support or timing.

From the agent checkout:

```sh
python tools/build_index.py --library-root ../library --kernels-root ../kernels
python tools/build_index.py --library-root ../library --kernels-root ../kernels --check
python tools/select_example.py --query 'mask predicate' --language en
python tools/select_example.py --pattern api.event_depths --language zh-CN
```

Exact IDs/owner paths rank first, then maintained phrases, then identifier/description
words. Results explain matching terms. Related reading is separate from selected scoped
examples. A failed filter never silently broadens the request; missing metadata remains
unknown. A no-match result links the owner directories.

When an owner adds or renames a folder, rebuild that owner's own index first
(`kernels/tools/build_index.py` for the gallery, `library/tools/api_examples.py` for the API
examples), then this one. Update relevant task
phrases and coverage, and run the guidance checks.

## What is actually in kernels.json

Schema `ascriptor.agent-kernel-index/1`, generated by `tools/build_index.py` and never
edited by hand. Alongside `release`, `source_roots`, `scope` and
`counts`, it holds 113 `candidates` — 58 library API examples and 55 kernel demos — plus a
`deferred_candidates` list, currently empty.

Both owners have the same entry shape, because both are four-file folders whose `metadata.json`
already carries the editorial fields. An entry carries `id`, `owner`, `source` — a **directory**
and not a file, for example
[`kernels/ascriptor_kernels/tutorials/mixed_pipeline`](../../kernels/ascriptor_kernels/tutorials/mixed_pipeline)
or [`library/examples/api/event_depths`](../../library/examples/api/event_depths) — `description`,
`guide`, `devices`, `topology`, `tags`, `cases`, `study_for` and `do_not_copy_when`, all copied from
that folder's own `metadata.json`. Each owner keeps its own word for the searchable API text: a demo
computes a `formula`, an API example exercises a `surface`.

`cases` is a **count**. Which cases exist is `python main.py --list` inside the folder, and printing
them here would be a second copy to keep in step. `pypto_pro_note` is true when a demo's `main.py`
carries a `# pypto_pro:` comment locating what the backend refuses, and an API example's `refusals`
lists the backends or launchers its `main.py` records a refusal for; in both the comment itself is
the statement and the index only says one exists. Nothing else in an entry describes where a folder
has run, because neither owner records anything of the kind.

## Data consumed by tools

| File | Schema |
|---|---|
| This navigation index | `ascriptor.agent-kernel-index/1` |
| [patterns.json](patterns.json) | `ascriptor.guidance-patterns/1` |
| Library API example index | `ascriptor.api-example-index/1` (`library/examples/api/index.json`) |
| Library API example metadata | `ascriptor.api-example/1` (a folder's `metadata.json`) |
| The example contract | [RFC-0012 section 3](../../library/docs/rfc/0012-product-contracts.md) |
| Kernel gallery index | `ascriptor.kernel-demo-index/1` (`kernels/index.json`) |
| Kernel demo metadata | `ascriptor.kernel-demo/1` (a folder's `metadata.json`) |

Case IDs, parameters and tolerances belong to the owner, not to this index: in both owners they
are the `CASES` list in that folder's `main.py` that `--list` prints. Index schema changes do not change kernel launch, precision or device qualification.
