# A2/A3 CCE 编写入口

使用 `ascriptor.a2` 或 `ascriptor.a3` 编写已声明的 A2/A3 形式，backend 为
`cce`。操作和设备范围以 owner API 契约为准，并在目标设备上执行完整任务负载。
完整源码身份由 [sources.json](../../../sources.json) 指定。

A2/A3 的 vector 操作直接作用于 UB Tensor，使用明确的 repeat/count、block
stride 和持续生效的 mask 状态。编写前读 [A2 vector API](../../../library/docs/api/a2-vectors.md)，
再研读完整的 [FMA 单元](../../../library/examples/api/a2_fma)。
目录自带尾块输入、独立 reference 和全部 case，共四个文件。它是 library 的样例，不是你的骨架：
写的时候 [`OpExec` 加你自己的比较](development-execution.md)就够了；A2 的算法 demo 在
[样例路线](../ROUTER.md)上加 `--device a2` 找。在该目录里：

```bash
python main.py --list
python main.py --launcher sim
python main.py --launcher pipesim
python main.py --launcher board --backend cce --device a2
```

`--launcher board` 在插着卡的那台机器上直接运行本源码快照；
[设备执行说明](development-execution.md#on-hardware)给出本地配置；`sim` 和 `pipesim`
在哪都能跑。A3 板使用 `--device a3`。
按[运行流程](../runtime-and-maintenance.md#hardware-first)检查设备、隔离任务并先上板。
功能模型和流水模型不能代替厂商编译与真实设备结果。

Cube 工作需读 [Cube API](../../../library/docs/api/cube.md)及单元的 L1/L0 物理几何。
A2/A3 的 Cube→Vector 经 GM 和显式所有权交接；A5 的 register/VF 与 L0C→UB
模式不能直接套用。INT4 MMAD 按完整字节读取，奇数逻辑 K 需要清理最后一个字节
的高半字节。[INT4 单元](../../../library/examples/api/a2_int4_tail)在设备端
规范化私有载体，允许原始输入有任意填充值。

[Anchor mask demo](../../../kernels/ascriptor_kernels/algorithms/a2_anchor_mask)提供相互
独立的滑窗和 synthetic causal 开关；边界由它的 `reference.py` 定义，`python main.py --list`
会逐条打印全部 20 个 case 及各自专门覆盖的点。A2/A3 的产品范围明确
只有 CCE，其他后端不列入后续计划。独立 A5PR facade、未声明的卷积 debug shape
和 optimizer 包 ABI 集成不在本次发布验收范围内。
